# Aves del Sur — business identity and domain reference audit

Checked 24 September 2026 after regeneration of the 48 static HTML pages. The supplied identity is **Aves del Sur**, `https://avesdelsur.com/`, `info@avesdelsur.com`. This report describes source files and generated output; it does not assert that the domain or mailbox is live.

| Check | Finding |
|---|---|
| Current production-domain references | `SITE_URL` in `tools/site/config.mjs` is `https://avesdelsur.com` (stored without final slash so paths append correctly); all 48 generated canonicals/OG URLs and schema identity URLs use that origin. `site/sitemap.xml` lists 47 absolute HTTPS URLs; `public/robots.txt` and `site/robots.txt` point to `https://avesdelsur.com/sitemap.xml`. |
| Incorrect domain references | No `http://avesdelsur.com`, `www.avesdelsur.com`, localhost/127.0.0.1, development-host or `example.com` references in generated page URL metadata. The `http://www.sitemaps.org/...` string is an XML namespace, **not** a fetched insecure asset or a site URL. Relative same-origin links for CSS/JS/favicon/navigation are intentional. |
| Current email references | `BRAND.email` in `tools/site/config.mjs` is `info@avesdelsur.com`; footer, `/contacto/`, legal notice and privacy policy display this email with direct `mailto:` links. Organization JSON-LD includes the same email on all 48 pages. A form notice and failure message also direct visitors to this address. |
| Incorrect/placeholder email references | The old `[PENDIENTE: email de contacto]` field was removed from source and regenerated HTML. No `@example.com`, `test@`, `hello@`, or `contact@` address was found in the relevant source/generated pages. Other **unverified** fields (legal name, tax ID, phone, hours, address, registration, legal terms) remain placeholders deliberately. |
| Business name | The generated site uses `Aves del Sur`; the brand name was already set and was not replaced. The TanStack fallback root in `src/routes/__root.tsx` retains imported “Lovable App” metadata, but this is not what the generated public HTML routes returned in development; review fallback/exception responses before production publishing. |
| Contact form destination | **None.** `data-endpoint=""`; no email service/server endpoint configured. The `action="/como-comprar/" method="post"` is intercepted by JS and is not a working delivery fallback. See [EMAIL-SETUP.md](EMAIL-SETUP.md). |
| Canonical/OG/schema status | Generated HTML uses absolute HTTPS canonicals, OG page/image URLs, Twitter image URLs, absolute BreadcrumbList and Article URLs, and Organization/WebSite IDs/URLs. There is no evidence supporting LocalBusiness address/phone, Product offers, ratings or social profiles, so none were invented. A standalone `twitter:url` tag was not added (the shared URL is canonical/OG). |
| Sitemap and robots | The route `/sitemap.xml` now serves the generated `site/sitemap.xml` instead of deriving a hostname/scheme from a proxy request. Its 47 URLs exclude `/404/`. The served public robots variant declares the full production sitemap. These checks are verified on the development server only. |
| Hosting/DNS | This Replit project was **not published** according to deployment metadata at audit time. Direct `curl` requests to the apex and www hosts did not resolve from this environment. A public DNS-over-HTTPS check returned no A answer for the apex and NXDOMAIN for `www` at audit time. Consequently HTTPS, certificate, HTTP→HTTPS and www→apex redirects **cannot yet be verified** on the live domain. DNS may change after this report. |
| Remaining manual work | Publish the app; connect apex in Replit Publishing → Domains; add the **specific A/TXT values Replit provides** at the registrar (current authoritative nameservers reported by DNS are Infomaniak), wait for domain verification and HTTPS, then test HTTP/HTTPS and host redirects. If www will be used, configure it separately and redirect it to the apex without a loop. Set up mailbox/MX and provider-provided SPF/DKIM/DMARC separately. Confirm other legal/business placeholders and a real form provider before claiming site/business readiness. |

Scope: searched site source and public assets for domain/email patterns and inspected generated HTML, robots, sitemap, JSON-LD and the running development preview. Dependency caches, uploaded briefs and historical audit documents are not production site references.
